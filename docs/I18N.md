# Internacionalización (i18n) — Guía completa

> **Esta es la guía de referencia para agregar y mantener traducciones en AnvilCraft Panel.** Si quieres contribuir un idioma, empieza por aquí.

## 📐 Arquitectura actual

```
src/lib/
├── i18n.ts                 # Setup de svelte-i18n (registra locales, fallback)
└── locales/                # ← AQUÍ viven las traducciones
    ├── en.json             # Referencia (SIEMPRE debe estar completa)
    ├── es.json             # Español
    └── <código>.json       # Cualquier otro idioma que se agregue
```

- **Motor:** [`svelte-i18n`](https://github.com/svelte-i18n/svelte-i18n) 4.0.1
- **Carga:** perezosa (lazy), cada locale se importa con `import()` dinámico
- **Fallback:** si una clave no existe en el locale del usuario, se usa `en.json`
- **Detección:** automática del navegador, con override en localStorage (`anvilcraft_locale`)

## 🌐 Idiomas soportados actualmente

| Código | Idioma | Estado |
|---|---|---|
| `en` | English | ✅ Completo (referencia) |
| `es` | Español | ✅ Completo |

Para ver la lista de locales registrados: `src/lib/i18n.ts:7-8`.

## 🛠️ Scripts npm disponibles

| Comando | Qué hace |
|---|---|
| `npm run translate -- fr` | Genera `src/lib/locales/fr.json` desde `en.json` usando Google Translate |
| `npm run translate -- fr de ja` | Genera varios idiomas en una corrida |
| `npm run translate -- --all` | Genera un set de 14 idiomas comunes |
| `npm run translate -- fr --engine libre` | Usa LibreTranslate en vez de Google |
| `npm run translate -- fr --force` | Sobreescribe si ya existe |
| `npm run translate -- --help` | Muestra todas las opciones |
| `npm run translate:validate` | Verifica que todos los locales tengan la misma estructura que `en.json` |

## 🚀 Flujo recomendado para agregar un idioma

### Paso 1 — Generar borrador automático

```bash
# Una sola vez: instalar dependencia
npm install

# Generar francés
npm run translate -- fr
```

El script:
- Lee `src/lib/locales/en.json`
- Lo traduce con Google Translate (motor por defecto)
- Guarda el resultado en `src/lib/locales/fr.json`
- Si el archivo ya existe, lo salta (usa `--force` para sobreescribir)

### Paso 2 — Revisar y ajustar

Las traducciones automáticas son **60-80% de calidad**. Hay que:

1. **Abrir el archivo** y leerlo completo.
2. **Ajustar términos técnicos del proyecto** (estos suelen quedar mal):
   - `instance` → "instancia" / "サーバー" (jp) / "实例" (zh) / usually English in fr/de/it
   - `loader` → "cargador" / usually left in English
   - `modpack`, `addon`, `world` → generalmente se quedan en inglés
   - `jar`, `java`, `minecraft` → **NUNCA** se traducen
3. **Revisar plurales y contexto**: Google Translate a veces produce traducciones literales raras.
4. **Revisar formato**: placeholders como `{name}` deben quedar intactos.

### Paso 3 — Validar

```bash
npm run translate:validate
```

Salida esperada:
```
📂 en.json tiene 487 claves

✓ en.json (referencia, 487 claves)
✓ es.json (485 claves, completo)
✓ fr.json (487 claves, completo)
```

Si faltan claves o sobran, el script las lista. **No commitear si hay errores.**

### Paso 4 — Probar localmente

```bash
npm run dev
# Abre la app
# Settings → Appearance → Idioma: Français
# O desde consola del navegador: localStorage.setItem('anvilcraft_locale', 'fr'); location.reload();
```

### Paso 5 — Commit y PR

```bash
git add src/lib/locales/fr.json
git commit -m "i18n: add French translation"
git push origin main
# Abrir PR en GitHub con título: "i18n: add <idioma> translation"
```

## 🔧 Motores de traducción alternativos

| Motor | Flag | Costo | Calidad | Requiere API key |
|---|---|---|---|---|
| Google Translate | `--engine google` (default) | Gratis | ⭐⭐⭐⭐ | No |
| Bing Translator | `--engine bing` | Gratis | ⭐⭐⭐ | No |
| LibreTranslate | `--engine libre` | Gratis (self-host) | ⭐⭐⭐ | Depende del server |
| DeepL | `--engine deepl` | Freemium | ⭐⭐⭐⭐⭐ | Sí |
| GPT-4 / Mixtral / Llama | `--engine gpt` | Costo de API | ⭐⭐⭐⭐⭐ | Sí |

**Recomendación:** Empezar con Google (gratis, sin setup). Si la calidad no es suficiente, evaluar DeepL o GPT.

## 🏗️ Agregar un nuevo idioma al sistema (registro)

Una vez que tienes el archivo `fr.json`, hay que **registrarlo** en `src/lib/i18n.ts`:

```typescript
// src/lib/i18n.ts
register('en', () => import('./locales/en.json'));
register('es', () => import('./locales/es.json'));
register('fr', () => import('./locales/fr.json'));  // ← NUEVO

const supportedLocales = ['en', 'es', 'fr'];  // ← Actualizar lista
```

Sin este paso, el archivo existe pero svelte-i18n no lo carga.

## 🆚 Cuándo considerar plataformas externas

Si el proyecto crece y tienes:
- **20+ contribuidores** de traducción recurrentes
- **10+ idiomas** mantenidos activamente
- Necesidad de **glosarios centrales** y **memoria de traducción**

…entonces conviene migrar a:
- **Weblate** (gratis para OSS, auto-PRs)
- **Crowdin** (gratis para OSS, UI muy pulida)
- **POEditor** (gratis hasta 1000 strings)

Hasta entonces, **GitHub PRs + json-translator** es la solución más simple, transparente y sin dependencias externas.

## ❓ Problemas comunes

### "Mi traducción nueva no aparece en la app"

1. ¿Registraste el idioma en `src/lib/i18n.ts`?
2. ¿El archivo está en `src/lib/locales/<código>.json` con el código correcto?
3. ¿El código del navegador es compatible? (`es-MX` → se reduce a `es` en `i18n.ts:23`)
4. Limpia localStorage: `localStorage.removeItem('anvilcraft_locale')` y reload.

### "El validador dice que faltan claves"

Probablemente `en.json` se actualizó y tu locale no. Opciones:
- Re-genera con `--force`: `npm run translate -- fr --force`
- O agrega las claves que faltan a mano copiando la estructura de `en.json`

### "Google Translate devuelve basura para mi idioma"

- Prueba otro motor: `--engine bing` o `--engine deepl`
- Si es un idioma de pocos hablantes, considera traducir a mano desde cero
- Para idiomas RTL (árabe, hebreo), verifica que el JSON se renderiza bien en la UI
